# PrinterCollector — описание для согласования с ИБ

**Версия:** 0.4.0 · 2026-05-12

## Назначение

Агент собирает счётчик отпечатанных страниц с локально подключённого принтера (USB) и отправляет показания на корпоративный сервер учёта. Решение проблемы: USB-принтеры не имеют IP-адреса и не опрашиваются по SNMP/HTTP, поэтому используется агент на ПК, к которому принтер подключён.

## Какие данные собирает

| Данные | Источник | Назначение |
|---|---|---|
| Имя принтера | `HKLM\SYSTEM\CurrentControlSet\Control\Print\Printers\<name>` | Идентификация устройства |
| Счётчик страниц (`PageCount`) | `HKLM\...\Printers\<name>\PrinterDriverData\PageCount` | Учёт печати |
| Серийный номер принтера | USB-дескриптор (Win32 API `cfgmgr32`) | Сопоставление с договором |
| `DeviceInstanceId` | `HKLM\...\Printers\<name>\PnPData` | Аудит USB-устройства |
| Имя ПК (hostname) | `Environment.MachineName` | Идентификация агента |
| Драйвер принтера | реестр | Информативно |

**Не собирает:** содержимое документов, имена документов, логин пользователя, файлы, скриншоты, нажатия клавиш, любую другую активность системы.

## Что отправляет на сервер

JSON-payload по HTTPS POST раз в час (или по нажатию «Опросить»):

```json
{
  "agent_id": "<hostname>",
  "agent_version": "0.2.0",
  "readings": [{
    "timestamp": "2026-05-07T07:22:44Z",
    "printer_name": "HP LaserJet 1020",
    "model": "HP LaserJet 1020",
    "serial_number": {"source": "device", "value": "<S/N>"},
    "counters": {"total_pages": 24690, "bw_a4": 24690, ...},
    "device_instance_id": "USB\\VID_03F0&PID_2B17\\<S/N>"
  }]
}
```

**Не отправляет:** ничего, кроме перечисленных полей. Никаких файлов, документов, метаданных пользователя.

## Сетевые потоки

| Поток | Куда | Когда |
|---|---|---|
| HTTPS POST `/api/v1/inventory/usb-agents/register/` | корпоративный сервер | один раз при первом запуске |
| HTTPS POST `/api/v1/inventory/usb-readings/` | корпоративный сервер | раз в час и при ручном запуске |
| HTTPS GET `/api/v1/inventory` | корпоративный сервер | при кнопке «Тест соединения» |

**Других сетевых обращений нет.** Агент не обращается в Интернет, не использует CDN, не отправляет телеметрию вендорам.

## Аутентификация и хранение секретов

- **Master key** — общий секрет, выдаётся ИБ-администратором при установке. Используется один раз для регистрации агента на сервере.
  - **Стирается из `settings.json` сразу после успешной регистрации** (минимизация поверхности атаки: после получения Bearer-токена master key больше не нужен).
  - В лог-файлах НЕ фигурирует (маскируется регексом `[0-9a-f]{64}` → `***`).
- **Bearer-токен агента** — выдаётся сервером после регистрации (256 бит энтропии).
  - Хранится в `settings.json` зашифрованным через **Windows DPAPI** (`DataProtectionScope.CurrentUser`). Расшифровать может только тот же Windows-пользователь на том же ПК.
  - На сервере хранится только **SHA-256 hash** токена. При утечке БД сервера plaintext не раскрывается.

## Транспорт

- HTTPS обязателен. Если ApiEndpoint в настройках начинается с `http://` (кроме `localhost` / `127.0.0.1` / `::1` для отладки в dev) — агент отказывается отправлять данные с явной ошибкой.
- TLS-валидация сертификата сервера включена (стандарт `HttpClient`). Custom-валидация и игнорирование ошибок сертификата отсутствуют.

## Локальное хранение

Все данные в общесистемном каталоге `%ProgramData%\PrinterCollector\` (`C:\ProgramData\PrinterCollector\`), чтобы агент работал одинаково для всех пользователей ПК:

| Файл/папка | Содержимое | Чувствительность |
|---|---|---|
| `settings.json` | endpoint, DPAPI-blob токена, имя принтера | средняя (master key стирается после регистрации) |
| `data\*.xml` | XML-копии каждого reading'а (для аудита) | низкая |
| `queue\*.json` | offline-очередь readings'ов (если сервер недоступен) | низкая |
| `collect.log` | лог запусков с временем, статусом, кодами ответа | низкая |
| `overrides.json` | ручные переопределения серийников | низкая |

**ACL:** при установке агент **явно** задаёт два ACE на каталог `%ProgramData%\PrinterCollector\` (через `icacls /grant`):

- `BUILTIN\Users:(OI)(CI)M` — чтобы GUI любого локального пользователя мог читать/обновлять `settings.json`, сохранять XML, видеть лог.
- `NT SERVICE\PrinterCollector:(OI)(CI)M` — чтобы служба под LocalService с **write-restricted** токеном (`sc sidtype restricted`) могла писать в свой рабочий каталог. Без этого ACE write-restricted token блокирует запись даже при наличии `Users:M`, потому что общие группы (Users, Authenticated Users) не входят в restricted-set токена.

Установка ACL делается во время запуска под admin (при установке службы из GUI).

DPAPI-blob токена шифруется в режиме `LocalMachine` — расшифровать его может любой процесс на машине, что необходимо для работы службы под LocalService и GUI под обычным пользователем с одной точкой хранения.

**Backward-compat:** при наличии legacy-настроек в `%APPDATA%\PrinterCollector\settings.json` (от установок до v0.3.0) агент мигрирует их при первом запуске, перешифровывает токен `CurrentUser → LocalMachine` (если расшифровывается под текущим юзером).

## Установка и автозапуск

1. **Развёртывание:** один файл `PrinterCollector.exe` (self-contained, .NET 8 runtime внутри). Не пишет в `Program Files`, не ставит драйверы.
2. **Первичная настройка** (требуется однократная admin-элевация):
   - Запустить EXE «От имени администратора» (для создания службы).
   - Указать endpoint сервера (HTTPS обязателен в production) и master key (выдаются ИБ).
   - Выбрать принтер из списка установленных.
   - Нажать «Зарегистрировать» → агент получает токен от сервера.
   - Нажать «Установить службу» → создаётся Windows-служба под `NT AUTHORITY\LocalService` и запускается.
3. **Автозапуск:** Windows-служба `PrinterCollector` (start type = auto-delayed). Долгоживущий процесс с внутренним таймером `PeriodicTimer` опрашивает принтер раз в час (значение из `ScheduleIntervalMinutes` в `settings.json`). Не зависит от того, какой пользователь залогинен.
4. **Эксплуатация (любым пользователем без admin):** запуск GUI без admin-прав показывает статус, текущий счётчик, лог. Менять службу / пере-регистрировать токен — только с admin-правами.
5. **Обновление EXE:** перед заменой бинарника GUI должен остановить службу (`sc stop PrinterCollector`), иначе файл залочен. После замены — `sc start PrinterCollector`.
6. **Удаление:** запуск EXE «От имени администратора» → «Удалить службу» (выполняет `sc stop` + `sc delete`) + удаление каталога `%ProgramData%\PrinterCollector\` + удаление EXE. Никакие системные настройки не остаются.

## Права и привилегии

- **Установка/удаление службы** требует admin (UAC) **один раз** (`sc create`/`sc delete` без admin отказывают).
- **Сам автосбор** работает под `NT AUTHORITY\LocalService` — встроенная **непривилегированная** локальная учётная запись Windows, без пароля, без членства в Administrators/Users, без интерактивного логона, без сетевой идентичности (на LAN ходит как `Anonymous`).
- **Service hardening:**
  - `sc sidtype PrinterCollector restricted` — в токене процесса появляется **per-service SID** `NT SERVICE\PrinterCollector` (`S-1-5-80-...`), токен переводится в **write-restricted** режим. Запись разрешена только туда, где явно дан ACE на per-service SID — то есть фактически только в `%ProgramData%\PrinterCollector\`.
  - `sc privs PrinterCollector SeChangeNotifyPrivilege/SeCreateGlobalPrivilege/SeIncreaseWorkingSetPrivilege` — `SeImpersonatePrivilege` и остальные дефолтные привилегии LocalService **отозваны**. Олицетворять другие токены агент не может.
  - `sc failure ... actions= restart/60000/...` — при падении процесса SCM автоматически рестартует службу через минуту.
- Чтение реестра — только `HKLM\SYSTEM\CurrentControlSet\Control\Print\...` (read-only).
- WMI-запросы — только `Win32_Printer` и `Win32_PnPEntity` (read-only).
- Не пишет в `HKLM`, не модифицирует другие службы, не загружает драйверы, не использует hooks/инжекции.

**Что не может агент даже при RCE в коде (благодаря LocalService + sidtype restricted + сокращённым privs):**

- читать профили других пользователей (`C:\Users\*`);
- писать в `Program Files`, `Windows`, `HKLM\SOFTWARE` (кроме явно выданных ACE на per-service SID);
- логиниться куда-либо интерактивно;
- олицетворять других пользователей (`SeImpersonate` отозван);
- получить admin-токен (не в группе Administrators).

## Зависимости и зависимости

- .NET 8 runtime — встроен в EXE (self-contained, изоляция от системного .NET).
- Внешние пакеты: `System.Management`, `System.Security.Cryptography.ProtectedData`, `Microsoft.Extensions.Hosting`, `Microsoft.Extensions.Hosting.WindowsServices` (только официальные Microsoft NuGet-пакеты).
- Нет: телеметрии, аналитики, third-party SDK, сетевых клиентов кроме `HttpClient` к корпоративному серверу.

## Исходный код

Открытый код, лежит в корпоративном Git. Безопасник может провести независимый аудит. Основные файлы:
- `Services/ApiClient.cs` — HTTP-клиент.
- `Services/AppSettings.cs` — настройки + DPAPI.
- `Services/PrinterReader.cs` — чтение реестра.
- `Services/UsbSerialReader.cs` — Win32 API для серийника.
- `Services/CollectorWorker.cs` — `BackgroundService` с `PeriodicTimer`, тело Windows-службы.
- `Services/HeadlessCollector.cs` — один тик сбора (используется и службой, и режимом `--collect` для ручной отладки).
- `Services/ServiceInstaller.cs` — обвязка `sc.exe` для установки/удаления службы с hardening-настройками.

## Известные ограничения (план развития)

1. **DPAPI `LocalMachine`.** Токен доступен любому процессу на машине (это by design необходимо для работы схемы «служба под LocalService + GUI под user»). Если злоумышленник получает code-execution на ПК — он получает и токен. Митигация: токен можно отозвать через admin-страницу сервера; токен ограничен только записью показаний счётчиков в проекте этой машины.
2. **Локальная служба**, без авто-обновления EXE. Обновление — `sc stop` → замена бинарника админом → `sc start`.
3. **Один принтер на агента.** Multi-printer на одной машине пока не поддержан (можно запросить).

## Что НЕ делает агент (явные гарантии)

- ❌ Не читает содержимое печатаемых документов.
- ❌ Не отслеживает имена пользователей в job-очереди принтера.
- ❌ Не отправляет данные никуда, кроме указанного корпоративного endpoint.
- ❌ Не имеет автообновления — обновление только через ручную замену EXE админом (после `sc stop`).
- ❌ Не открывает прослушивающих портов, не принимает входящих соединений.
- ❌ Не требует admin-прав ни на установку, ни на работу.
